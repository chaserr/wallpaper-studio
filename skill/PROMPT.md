# 一段提示词：从零做一个 Windows 本地桌面工具

把下面整段复制给 AI，把开头方括号里的内容换成你的项目。不需要它读任何附件。
（想要更完整的版本，看同目录下的 [`win-local-desktop-app/`](win-local-desktop-app/) —— 那是个带骨架代码和踩坑清单的 skill。）

---

我要做一个 Windows 本地桌面小工具，主题是【一句话说清做什么，比如：把一堆照片按拍摄日期重命名并归档】。

**技术要求，请严格按这个来：**

1. **只用 Python 标准库**，能不用第三方依赖就不用。pywebview 用于原生窗口、ffmpeg 用于视频解码这类，允许作为「可选依赖」——缺了要能降级，不能报错退出。
2. 架构固定为：一个 `ThreadingHTTPServer` 监听 `127.0.0.1`，提供静态页面和 JSON API；界面是一个自包含的 `ui/index.html`（HTML + CSS + JS 全在一个文件里）。Python 进程里需要碰 Windows 原生能力的地方用 `ctypes`。
3. UI 文件**每次请求从磁盘读**，不要缓存，这样改完刷新就生效。
4. 数据目录单独定，默认 `E:\<AppName>Data`（没有 E 盘则落到 `图片\<AppName>Data`），支持环境变量覆盖。程序和数据分离，用户能直接打开文件夹看到原始文件。
5. 所有接口统一返回 `{"ok": true, ...}` 或 `{"ok": false, "error": "给用户看的一句话"}`。前端只写一个 `api()` 统一解析。
6. 所有来自前端的数值，后端一律先过一层清洗函数：`None` / `""` / `NaN` / 非数字 → 回默认值，并夹在合法区间内。写配置文件用「临时文件 + `os.replace`」原子替换，`json.dump` 加 `allow_nan=False`。
7. 端口从 8770 往上试 10 个；启动前先探测是否已在运行，已运行就直接把 URL 丢给浏览器，不要开第二个实例。
8. 要做原生窗口就在建窗前声明 DPI 感知（`SetProcessDpiAwarenessContext(-4)`），否则 4K + 200% 缩放下窗口只画一半。窗口起不来（缺 WebView2）要自动退化成浏览器标签页。
9. 前端所有异步列表都要有竞态令牌（自增序号，回包时比对），防止快速切页时旧数据覆盖新页面。
10. 前端加全局 `error` / `unhandledrejection` 监听，把错误 POST 到 `/api/log` 写进本机日志——打包成无控制台的 exe 后，这是唯一能看到报错的途径。

**界面要求：** 干净、留白足、没有广告位。列表用事件委托（判断 `data-act`），别在每次重渲染后重新绑事件。需要图片列表时用 `loading="lazy"`。

**打包要求：** PyInstaller `onedir`（不是 onefile），`console=False`。打包后必须实测三件事：进程能起来、端口能通、核心接口返回 200。源码能跑不代表打包能跑。

**发布要求：** 打成 zip（解压后是一个文件夹，不要散在根目录），用 `gh release create` 发 GitHub Release，标题写清这版最重要的一件事，正文分「修了什么 / 加了什么 / 去掉了什么」。发布后用 `gh release view --json assets` 确认资产真的传上去了。zip 资产名用 ASCII，中文名可能被静默丢弃。

**请按这个顺序做，每步做完告诉我结果：**

1. 目录结构与数据目录探测 → 跑通一个空页面
2. 核心数据读写 + 一个列表接口 → 页面上能看到真实数据
3. 主功能（增删改 / 处理流程），每加一个就实机验证一次
4. 接 Windows 原生能力（如有）
5. 边界测试：空数据、非法参数、断网、超大文件
6. 打包 + 冒烟测试 + 发版

**不要做的事：**

- 不要引入 Flask / FastAPI / Electron / Tauri，也不要为了「架构好看」拆出十几层抽象
- 不要在前端硬编码后端的错误文案映射，错误信息由后端直接给
- 不要在源码里写死开发机的绝对路径
- 不要在没有实测的情况下说「已完成」——每个功能都要有可复现的验证步骤
- 不要把 `config.json`、日志、打包产物提交进仓库
